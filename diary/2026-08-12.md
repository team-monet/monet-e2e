## Finding 14 — `dismiss` is a pure no-verdict close: no body, no revision, no observation
### 14a. dismiss works WITHOUT `body` even on a multi-observation concept
Contrast with run 9's finding 13b: `accept-new` on a 2+ prior-observation
concept is REFUSED without a reconciled body (anti-guess guard — superseding
an arbitrary prior would be a guess). `dismiss` on the SAME fixture succeeds
body-less: it supersedes nothing, so no guess is being made. The guard is
verdict-specific, not contradiction-wide.

### 14b. dismiss closes the contradiction
`memory_overview`: openContradictions empty, `counts.disputed` = 0.
Data layer: the contradictions row is RETAINED with `status='dismissed'`
(terminal), `resolved_by='monet-e2e-test'`, `resolved_at` populated, `kind`
kept ('value-conflict'). No row deletion.

### 14c. dismiss leaves body/observations/revisions untouched
- Concept body unchanged (observation appends from store time remain — the
  CORRECTION observation text is legitimately in the body because stores
  append; what dismiss must NOT do is inject a verdict text).
- obsCount unchanged (no new observation row).
- **concept_revisions: ZERO rows for dismiss** vs exactly 1 for
  accept-new-with-body on the same fixture. Revisions record body-changing
  ops only; dismiss changes no body.
- needsSynthesis stays True (the correction observation re-armed it; resolve
  is not a synthesize — consistent with run 9 finding 13).

### 14d. verdict matrix now complete (accept-new vs dismiss)
| Aspect | accept-new (w/ body) | dismiss |
|--------|---------------------|---------|
| body required on 2+ obs | YES (refused otherwise) | NO |
| concept body | replaced with reconciled body | unchanged |
| concept_revisions row | +1 | +0 |
| observations | unchanged | unchanged |
| contradiction row | retained, terminal status | retained, `status='dismissed'` |
| needsSynthesis | untouched (stays True) | untouched (stays True) |
| disputed count | 0 after | 0 after |

# 2026-08-12 — Run 11-RE (reverse-engineering): contradiction processing DOCUMENTED

## What was done
Next module after run 10's schema migration: **contradiction processing** (flag /
mediate / dismiss) in `@team-monet/monet` v1.5.2 (`dist/index.js`), using the /tmp
python helpers (mscan.py/mdump.py) against the minified bundle. No `-d` experiment
needed — all evidence is source-level. This run also answers the E2E agent's open
follow-ups from runs 9/11 (guard source, `reconciledBody` naming, `dismissed` vs
`resolved` status strings — RE-13 candidate).

## Findings
1. **Auto-flag on correction ATTACH**: the store path opens a contradiction
   (`kind='value-conflict'`, `observationId` = the correction, `detail:
   "correction: <first sentence ≤80 chars>"`) only when the correction ATTACHES to an
   existing concept (`A=true`). A correction that creates a new concept opens NO
   contradiction (RE-14 candidate).
2. **`flagContradiction`** (also manual `memory_flag_contradiction`, kinds
   value-conflict/staleness/scope-conflict): inserts row `status='open'`, sets concept
   `status='disputed'`, confidence −0.3 (floor 0.1), arousal +3. Rules can't be flagged
   (must be corrected); source/retired concepts immutable.
3. **`resolveContradiction` holds BOTH verdict branches in ONE function**:
   - `dismiss` → `UPDATE contradictions SET status='dismissed', resolved_at, resolved_by`
     — NO body handling, NO supersession, NO revision (matches E2E finding 14).
   - `accept-new`/`keep-current` → supersede losers, optional body replace +
     `writeRevision(version+1)`, then `status='resolved'`, `resolution_obs_id` =
     correction id (accept-new) or NULL (keep-current), last_confirmed + arousal +1.
   - **Anti-guess guard** exact condition captured: fires only for accept-new with
     ≥2 live priors, no contradictedObservationId, and no body — matches E2E 13b
     boundary (prior=1 OK, prior≥2 refused). There is NO `reconciledBody` param —
     the actual param is `body` (prose only).
4. **Concept status is DERIVED**: `recomputeNativeConceptProjection` writes
   `status = CASE WHEN open_count>0 THEN 'disputed' ELSE 'active' END` on every
   recompute — that (not an explicit update) restores 'active' after the last
   contradiction closes. Disputed caps confidence at 0.5; resolved contradictions add
   +0.2 to the confidence factor; flag/resolve move arousal ±3/+1.
5. **Pair-flag dismissal** (`memory_resolve` conceptAId+conceptBId): operates on
   `memory_edge` (types possible_duplicate_of / extraction_candidate), sets
   `dismissed_at`/`dismissed_by`; idempotent `rowsUpdated:0` no-op. Not contradictions.
6. **Dismiss with a body is silently ignored** (pre-answers E2E run-11 next-step #2).
7. Status vocabulary ('open'/'resolved'/'dismissed') is raw literals in 6+ functions —
   **no shared enum** (RE-13 CONFIRMED).

## Issues found (RE-13..RE-15)
- RE-13 (confirmed from E2E run-11): contradiction statuses are scattered magic
  strings, no enum; both verdict statuses live in the same function (not
  version-dependent in v1.5.2), plus `resolved_by` sentinels 'retireConcept'/
  'sync-tombstone'.
- RE-14 (new): correction stores that fail to attach open no contradiction — the
  challenge never reaches the prior concept's mediation flow.
- RE-15 (new, latent): fetch-card `status`/`openContradictions` depend on the derived
  column; all current closers recompute, so no live bug, but the coupling is implicit.

## Finding 16 — dismiss is verdict-orthogonal to synthesize state
### 16a. dismiss on a SYNTHESIZED concept behaves identically to a plain one
The full test15 semantics carry over unchanged when the concept was
synthesized first: dismiss without `body` succeeds on a multi-observation
concept, closes the contradiction (open=0, disputed=0), keeps the concept body
(synthesized body + observation appends; no verdict rewrite), writes no
observation, and writes NO concept_revisions row beyond the synthesize's own
(1 = synthesize only). Verdict handlers do not touch synthesize state.

### 16b. dismiss WITH a body silently ignores the body (RE finding 6, E2E-confirmed)
Passing `body` to `memory_resolve` with `decision=dismiss` succeeds and closes
the contradiction exactly like body-less dismiss, but the body is dropped: no
verdict text in the concept body, no extra concept_revisions row (revisions
record body-changing ops only, and dismiss changes no body even when asked).
Matches the source-level finding from RE run 11 ("dismiss with a body is
silently ignored") — now pinned E2E with the data layer.

### 16c. needsSynthesis stays True after dismiss on a synthesized concept
The correction observation re-armed the flag (test13/14 finding); dismiss does
not clear it — resolve is not a synthesize, and the flag is not "restored" to
the pre-correction False state. Same for accept-new (test14) and plain dismiss
(test15): the flag survives any resolve verdict.
