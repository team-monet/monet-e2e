## Key findings (product/ops)
1. **Fresh isolated DB pins `Xenova/bge-small-en-v1.5`** (384-dim) — differs from the `all-MiniLM-L6-v2`
   default documented in the ops skill. The installed version's default changed.
2. **Korean rejection guard on English-only embedders**: store/search refuses with an explicit error
   ("This content is 67% non-Latin script... would be stored and then never found").
   It's a pre-block, not a store-and-never-find problem — an improvement in 1.5.1+.
3. **repair target format**: `--target 'onnx:Xenova/...'` fails with "invalid model ID".
   A **bare model ID** (`--target Xenova/paraphrase-multilingual-MiniLM-L12-v2`) works.
4. **MCP tools/call responses** are wrapped in standard content blocks (`[{type:text, text:"<json>"}]`).
   Added the `call_json` parsing helper.
5. **memory_reassign_circle** requires the current `circle` param explicitly. `resolution: "auto"`
   dedup-merges into a similar destination concept; `"forceNew"` moves as a distinct concept.
6. **Re-resolution constraint**: repeated corrections on an already-resolved concept reject
   `accept-new` with "no reconciled body" — needs `contradictedObservationId`. Tests use unique circles.
7. **doctor diagnosis**: plain `doctor` reports `Assessment: unknown`; only `--check-provider`
   shows `safe` + `Provider: available`.
