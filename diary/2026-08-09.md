## Scenario 7 — schema migration (real old-version fixture)
1. **Fixture generation**: installed `@team-monet/monet@1.2.4` into a temp prefix
   (`~/.monet-test/prefix-old`, node@22) to create a genuine 1.2.4-era DB.
   Old version: serverInfo 0.7.0, 15 tools, default embedder all-MiniLM-L6-v2, 12 tables
   (no sync_meta/embedder_migration — schema 4).
2. **Migration detection**: new-version (1.5.1) doctor reports the old schema precisely —
   `Schema: 4 (supported: 12)` + `Assessment/Pin/Migration: unknown`.
3. **Auto-migration**: opening the new server migrates 4 → 12 automatically.
   Post-migration store/search works; the **old observation is preserved and retrievable**.
4. **Post-migration state**: `Schema: 12`, `Migration: none`,
   **Pin: Xenova/all-MiniLM-L6-v2 (source: backfilled)** — not the fresh-DB default
   (bge-small-en-v1.5). Design preserves embedder consistency with existing vectors.
5. **Re-run safety (GR-06)**: fixture copied to a scratch dir each run → pristine copy untouched.

## Scenario 9 — concurrency (2 processes × same DB)
