# 2026-08-16 — Run 36 (E2E): full-suite regression → disk-full ENOSPC → model-cache fix

## What happened — regression found
The full suite FAILED 3 tests: test25 (RE-30), test26 (RE-23), test28 (RE-24) — all
three are the **source-subsystem** tests. Each crashed with `RuntimeError: server closed
stdout / timeout` during `initialize()` (server startup), not an assertion failure.
Suite dropped from the expected `21/32 pass + 10 xfail + 1 xpass` to
`21 pass + 7 xfail + 1 xpass + 3 FAIL`.

## Root cause — ENOSPC (disk full) + model re-download
Reproduced test25 standalone with full stderr capture. The server printed:

```
[monet-core] loading local embedding model (Xenova/bge-m3:cls:q8; first run downloads once)…
[monet-core] loading model files… 549.6 MB read
[monet-core] the cached model also failed to load … file was not found locally …
[monet-core] Xenova/bge-m3:cls:q8 unavailable (ENOSPC: no space left on device, write)
```

`df -h` confirms `/System/Volumes/Data` is **100% full (657 MB free)**. The source tests
redirect `HOME` to a temp dir to isolate source storage (RE-29), which ALSO moves the
embedder model cache (`~/.monet/models`) into the empty fake home — so the server
re-downloads the ~550 MB bge-m3 model on EVERY source-test run. With <550 MB free the
download dies with ENOSPC, the semantic embedder is unavailable, a NEW store refuses the
lexical fallback, and the server exits → the client sees "server closed stdout".

## Fix — MONET_MODEL_CACHE points the cache back at the real location
The installed 1.6.1 honors `MONET_MODEL_CACHE` (bundle: `process.env.MONET_MODEL_CACHE
?.trim(); return e ? Be(e) : Be(homedir(), ".monet", "models")`; readable source
`resolveModelCacheDir()` tested in `embedding-onnx.test.ts`). Added to test25/26/28
(module level, before the HOME override):

```
REAL_MODEL_CACHE = os.path.join(REAL_HOME, ".monet", "models")
os.environ["MONET_MODEL_CACHE"] = REAL_MODEL_CACHE
```

so the server reuses the cached model read-only and never re-downloads. This is the SAME
read-only model load the non-source tests already do every run (they don't redirect HOME)
— it writes nothing to `~/.monet/models` and does NOT touch the prod store
`~/.monet/monet.db` (GR-01 intact).

## Verification
- test25/26/28 standalone → all back to XFAIL (RE-30 EACCES, RE-23 silent `[]`, RE-24
  silent de-auth), model loaded from cache.
- Full suite re-run: **21/32 passed, 10 xfail, 1 XPASS (RE-19), 0 fail** — green again.
- Side benefit: source tests now run in 1.5–2.5 s (were 19–23 s) — no more 550 MB re-download.

## Findings

### storage.md

  `BetterSqlitePort` is a thin pass-through over better-sqlite3.
- WAL + `busy_timeout = 5000` support the ONE-server + ONE-CLI shared topology; `journal_mode =

  migrate/change journal mode); `readStoredVectorPresence` returns `false`/`null` distinctly so

### embedding.md
- `EmbeddingProvider` is the model-adapter seam; thresholds + four per-space flags
  (`inputWindow`, `countTokens`, `needsLexicalArm`, `reliableSegmentTokens`, `nativeScoreFloor`,
  `readsOnlyLatinScript`) travel WITH the embedder; omitted = permissive (no gate on a guess).
- `HashingEmbeddingProvider` is tokenizer-VERSIONED (`HASHING_TOKENIZER_VERSION = 2` fresh, v1
  ASCII-only resurrected for old pinned stores) — the version number IS the vector space's
  identity; `modelId = hashing:dim=<dim>:tok=<ver>`.
- Vector helpers: `cosine` = dot (L2-normalized), `blend` running-mean, `blendWeighted`
  support-weighted merge, `embToJson`/`jsonToEmb`, `isZeroVector` placeholder marker, `normalize`
  zero-guard, `hash32` FNV-1a + sign hashing.

### store-embedder.md
- `chooseStoreEmbedder` is the THREE-STATE startup decision (pinned / legacy-vector-bearing /
  fresh) run before `MonetCore` construction; pins are authoritative and REQUIRED to load; a
  wrong embedder refuses (`PinnedStoreEmbedderUnavailableError`) rather than silently comparing
  two spaces.
- The `null`-vs-`false` subtlety in `readStoredVectorPresence` (only a confirmed `true` licenses
  the legacy path; unknown is treated like fresh) is the fix for the silent-lexical-downgrade bug.
- `requireSemanticOrExplicitLexical` refuses implicit hashing fallback; `MONET_EMBEDDER=hashing`
  stays the explicit opt-in.
