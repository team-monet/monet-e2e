## What changed (readable TS, packages/core + packages/cli)

### #51 — "Make the gate's record say which rule blocked, and surface the read dimension"
- **`gate-journal.ts`** — new `blockingRuleIdsOf(rules)` helper: returns
  `{ blockingRuleIds }` only when a blocking rule matched, else `{}`. Shared so
  the two writers ("core-gate" and "gate-cli") stop drifting (monet#37).
- **`gates.ts`** — `gateStats` gains `byStageRead` (per-stage count of
  `stage_lookup` "recognized" deliveries, `rule_count > 0`, liveness-scoped).
  New index `idx_gate_events_stage_lookup ON gate_events(matched_stage_id,
  matcher, circle, ts)`, created in `migrateGateColumns` AFTER the `matcher`
  column guard (the CREATE-before-ALTER ordering bug was caught by the suite's
  schema-upgrade test).
- **`engine.ts`** — `MemoryOverview.gateStats` gains `unreadStages` (zero-read
  stages, capped at `OVERVIEW_EXCEPTION_LIMIT`=10) + `unreadStagesOmitted`.
  The hook-path journal write now uses `...blockingRuleIdsOf(result.rules)`
  instead of the inlined (and silently-skipped) version.
- **`mcp-server.ts`** — `fitOverviewEnvelope` drops `unreadStages` the same way
  as `unexplainedDenies` (count survives via `unreadStagesOmitted`).
- **`render-overview.ts`** — renders `unread/{windowDays}d [id] name` lines and
  a `no curation work queued` gate now also consults `unreadStages`.

### #58 — "Hook sends rule identity and a read instruction, not clipped rule text"
- **`gate-cli.ts`** — `formatRuleLine` (`text — reason`, 80-char clip) replaced
  by `formatGateInstruction`: identity-only payload (matched stage names,
  blocking count, an instruction to read via `stage_lookup`), capped at
  `INSTRUCTION_STAGE_CAP`=8. The `reason` field is now delivered by
  `stage_lookup` (pull), not pushed by the hook. Deny discloses blocking
  concept ids + mirror generation + "later edit is unrecoverable".
- **`install-cli.ts`** — the deny path now writes `enforced: true` (monet#37);
  the advisory `additionalContext` appends a timing sentence (advisory arrives
  beside the result, not before the call).
- **`engine.ts` / `gates.ts` / `mcp-server.ts`** — the `reason` field's
  describe strings + error wording change from "shown when the gate fires" to
  "delivered by stage_lookup, not by the gate payload".
- **`index.ts`** — re-exports `CIRCLE_NAME_MAX_CHARS` (so the gate payload
  can't restate the stage_lookup circle bound and drift from it) and
  `blockingRuleIdsOf`.

### #37 — conformance attribution (folded into #51)
- **`conformance.ts`** — `computeConformance` now folds the two sibling mouths
  (wrapper + `monet gate`) into one fire via `foldChainsToOneFire` (representative
  = line naming the most rules) and reads `enforced` across the chain via
  `buildChainEnforced`. `verdictRuleIds` absent ⇒ single-rule fire (was "applies
  to all"); empty ⇒ "unavailable" (multi-rule fire with no recorded blocking ids
  → no rule credited, reason string appends the caveat). `annotatedScoped` lets
  a prior annotation written under the OLD contract be re-annotated once.

## Priority #2 — upstream #59 → RE-49 (stage_lookup clips body/reason, no recovery path)

Verified against `packages/core/src/mcp-server.ts` (current `main`):

- `clip()` (146-150) returns `{text, clipped}` and writes an inline
  `…[truncated N chars]` marker — matches the issue's quote byte-for-byte.
- `stage_lookup` handler (1595-1625) computes `bodyClip`/`reasonClip` but uses
  ONLY `.text`; the `.clipped` flag is **discarded**. No `bodyTruncated`/
  `reasonTruncated` field is emitted. `conceptId` IS returned (1598), so the
  recovery path exists (`memory_fetch(conceptId)`) but is undisclosed.
- `memory_fetch` already solves this: emits `...(body.clipped ? {bodyTruncated:true} : {})`
  (1519) and its tool description says "`bodyTruncated` means recover from
  observations" (1407). `stage_lookup` has the same problem and neither the flag
  nor the instruction.
- `stage_lookup` tool description (1566) promises "omission recovery fields" —
  those are `rulesOmitted`/`omittedRules` (omitted RULES, the 3-tier ladder),
  NOT clipped body/reason. The gap is real and un-addressed.
- Caps confirmed at `gates.ts:2018-2021` (`STAGE_LOOKUP_RULES_CAP`=200,
  `BODY_CAP`=6000, `REASON_CAP`=1200, `OUTLINE_CAP`=500) — already in METRICS.

**E2E-verifiable: yes** (MCP surface, `stage_lookup` is one of the 23 tools, not
halt-listed). Desired contract: the response discloses
`bodyTruncated:true`/`reasonTruncated:true` when clipped (mirroring `memory_fetch`),
so a caller can `memory_fetch(conceptId)` to recover. Currently absent → XFAIL.
Registered as **RE-49 (S3, open)**. Flagged as E2E follow-up **test39**.

## Priority #3 — upstream #13 → RE-50 (startup can't say why it died)

Verified against `packages/core/src/mcp-server.ts` + `packages/core/scripts/mcp-cli.ts`:

- `createMonetCoreMcpServer` is now at mcp-server.ts:3454 (the issue cited
  3358-3414 — pre-monorepo line numbers; the investigation is unchanged).
- `await core.ensureEmbedderPin()` (3466) — model load/warm/download — runs
  BEFORE `new McpServer` (3467): the server object does not exist until the pin
  is satisfied.
- `new StdioServerTransport()` (3490) + `await server.connect(transport)` (3491)
  — the protocol channel opens **LAST**. Every throw before 3491 leaves no MCP
  channel; the host sees only "Connection closed" (-32000).
- The factory's try/catch (3489-3508) wraps only connect + scheduler attach;
  `ensureEmbedderPin()` (3466) and the entry points' store-open + model-load are
  OUTSIDE it.
- Entry point `packages/core/scripts/mcp-cli.ts:38-51` confirms the fallible
  region is wider than the factory: `new MonetCore(dbPath, { embedder: await
  chooseStartupEmbedder(dbPath) })` opens the store AND loads the model before
  `createMonetCoreMcpServer(core)` (52). `main().catch()` (61-66) writes the
  cause to stderr + exit 1 — invisible on a stdio transport.

**E2E-verifiability judgment: structural/design.** The fail-closed order is
deliberate (never substitute another embedder — see `instantiateEmbedderForPin`),
so fixing the opaque exit requires a design decision (degraded serving mode vs
out-of-band diagnosis vs narrowing causes), not a pure reorder. No clean
behavioral XFAIL without the design answer. Registered as **RE-50 (S2, source)**
→ L2 routing (design-decision queue).
