## What changed (readable TS, packages/core + packages/cli)

### #51 — "Make the gate's record say which rule blocked, and surface the read dimension"
- **`gate-journal.ts`** — new `blockingRuleIdsOf(rules)` helper: returns
  `{ blockingRuleIds }` only when a blocking rule matched, else `{}`. Shared so
  the two writers ("core-gate" and "gate-cli") stop drifting (monet#37).
- **`gates.ts`** — `gateStats` gains `byStageRead` (per-stage count of
  `stage_lookup` "recognized" deliveries, `rule_count > 0`, liveness-scoped).
  New index `idx_gate_events_stage_lookup ON gate_events(matched_stage_id,
  matcher, circle, ts)`, created in `migrateGateColumns` AFTER the `matcher`
  column guard (the CREATE-before-ALTER ordering bug was caught by the suite's
  schema-upgrade test).
- **`engine.ts`** — `MemoryOverview.gateStats` gains `unreadStages` (zero-read
  stages, capped at `OVERVIEW_EXCEPTION_LIMIT`=10) + `unreadStagesOmitted`.
  The hook-path journal write now uses `...blockingRuleIdsOf(result.rules)`
  instead of the inlined (and silently-skipped) version.
- **`mcp-server.ts`** — `fitOverviewEnvelope` drops `unreadStages` the same way
  as `unexplainedDenies` (count survives via `unreadStagesOmitted`).
- **`render-overview.ts`** — renders `unread/{windowDays}d [id] name` lines and
  a `no curation work queued` gate now also consults `unreadStages`.

### #58 — "Hook sends rule identity and a read instruction, not clipped rule text"
- **`gate-cli.ts`** — `formatRuleLine` (`text — reason`, 80-char clip) replaced
  by `formatGateInstruction`: identity-only payload (matched stage names,
  blocking count, an instruction to read via `stage_lookup`), capped at
  `INSTRUCTION_STAGE_CAP`=8. The `reason` field is now delivered by
  `stage_lookup` (pull), not pushed by the hook. Deny discloses blocking
  concept ids + mirror generation + "later edit is unrecoverable".
- **`install-cli.ts`** — the deny path now writes `enforced: true` (monet#37);
  the advisory `additionalContext` appends a timing sentence (advisory arrives
  beside the result, not before the call).
- **`engine.ts` / `gates.ts` / `mcp-server.ts`** — the `reason` field's
  describe strings + error wording change from "shown when the gate fires" to
  "delivered by stage_lookup, not by the gate payload".
- **`index.ts`** — re-exports `CIRCLE_NAME_MAX_CHARS` (so the gate payload
  can't restate the stage_lookup circle bound and drift from it) and
  `blockingRuleIdsOf`.

### #37 — conformance attribution (folded into #51)
- **`conformance.ts`** — `computeConformance` now folds the two sibling mouths
  (wrapper + `monet gate`) into one fire via `foldChainsToOneFire` (representative
  = line naming the most rules) and reads `enforced` across the chain via
  `buildChainEnforced`. `verdictRuleIds` absent ⇒ single-rule fire (was "applies
  to all"); empty ⇒ "unavailable" (multi-rule fire with no recorded blocking ids
  → no rule credited, reason string appends the caveat). `annotatedScoped` lets
  a prior annotation written under the OLD contract be re-annotated once.
