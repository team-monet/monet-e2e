  a bad dbPath — achieved by registering into a fresh dir then making its

## Finding: cli/remote-circle.ts is a coverage-metric FALSE LEAD (same class as bootstrap.ts)

`remote-circle.ts` is three pure git-remote helpers (no sqlite in the module
graph — extracted from circle.ts as a P1 fix, PR #40):
- `getOriginRemote(projectDir)` — `git -C <dir> remote get-url origin`, "" on
  failure (2 branches: url vs catch).
- `canonicalRemoteKey(remote)` — the branchy canonicalizer (URL-schemed
  ssh/https/git × userinfo-strip × scheme-specific default-port strip ×
  non-default-port keep; SCP-like form; `.git/` trailing-slash order; path-case
  preservation; credential-free fallback).
- `defaultNameFromRemote(remote)` — `host/org/repo` → hyphen slug, no-slash
  sanitize, `"project"` on empty (3 branches).

Reached at two call sites: `circle.ts` (live `deriveCircle`/checker, `monet
start`/`status`) and `gate-cli.ts` offline `--circle` resolver
(`resolveGateCircle`, remote-aware pick).

**Upstream evidence (the deciding fact):** the monet monorepo unit-tests these
exhaustively — `cli/src/__tests__/circle.test.ts` has **35 `canonicalRemoteKey`
references** and asserts SSH/HTTPS normalization, cross-host no-collision,
scheme-specific default-port stripping (ssh:443/https:22 kept), non-default-port
keep (:2222≠:2223), `.git/` trailing-slash parity, SCP form, folder-hash
fallback, getOriginRemote empty/throw paths, defaultNameFromRemote no-slash
sanitize — plus `gate-cli.test.ts` and `install-cli.test.ts` re-drive the same
helpers. Same signature as bootstrap.ts (run 56): the logic is fully behavior-
tested upstream; the monet-e2e 69-line gap exists only because run_cli never
re-drives these branches against the built binary.

**Verdict:** a monet-e2e driver/scenario re-driving these remote forms would
inflate the self-measured coverage % from 53.7% toward ~95% but add ZERO new
independent behavioral verification — the behavior is already asserted
upstream. Skip with rationale (mirrors run 56 on bootstrap). → reconcile
monet-e2e#23 for the supervisor.
