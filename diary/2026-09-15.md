## Finding — RE-58 (S2, `confirmed`, guard `test58`, XFAIL)

**A store stamped ABOVE this build's supported schema opens, is bootstrapped, and is SERVED — while
`monet repair` refuses the very same store.**

| probe | arm A: bare store, 0 tables, `user_version=14` | arm B: real seeded store, stamped 14 |
|---|---|---|
| `monet start` | **accepted**, no refusal, stderr `Monet started` | **accepted** (`Monet started` + banner) |
| store after open | `user_version` **stays 14**, tables **0 → 27**, `-wal`/`-shm` created | `user_version` 14, seeded observation still returned by `memory_search` |
| writes | `memory_store` + `memory_search` succeed; the row survives a **second, independent session** | — |
| `monet doctor` | `Schema: 14 (supported: 13)`, `Assessment: unknown` (rc 2) | same |
| `monet repair` | **refuses** — `Store schema 14 is newer than supported schema 13; refusing repair.` (rc 1) | same |

Answers to #107's three open questions, measured: **(1) which statement throws first — none.**
Nothing throws; the version ladder is skipped above the ceiling while the idempotent,
`table_info`-guarded table-ensuring DDL runs **unconditionally**, so a store this build cannot name
gets a full 27-table layout stamped onto it. **(2) what the message says — there is no message**: the
deferred failure is deferred past every surface a user touches. **(3) whether anything writes before
it does — yes, and that write is the engine's own bootstrap DDL**, so "the store is untouched
because the caller wrote nothing" is false.

Framed conservatively: every later write into such a store is unsupported **by construction** (an
older binary writing rows a newer schema may read differently), but **no data loss was observed in
this run** — the measured defect is the silent acceptance, not demonstrated corruption.
`monet repair` refusing what `monet start` serves is the operational trap: the user gets a
working-looking server and a refusal from the one tool that would have said "upgrade first".

## Guard (new, `tests/test58_re58_schema_ceiling_shipped.py`)

Two arms (bare-0-table and seeded-real), 4 **stable invariants** that must hold before AND after the
fix (`doctor` schema line, `Assessment: unknown`, `repair` refusal text + rc≠0, `user_version`
unchanged after the journey) plus repro checks that run only while the bug is present (a broken
reproduction = exit 1, so the test cannot silently "pass" for the wrong reason). The flip signal is
the **REFUSAL only**: per upstream #156 the fixed CLI still writes the circle map before refusing,
so asserting a write-free store would turn the fix into a FAIL. `supported` is parsed from the
product's own doctor line (no hardcoded 13), so the guard survives the next schema bump.
Standalone runs: **EXIT=2 (XFAIL) ×3** (initial + 2 re-run-safety passes), temp stores only.
