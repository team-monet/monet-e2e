## Conformance contract pinned (the §4/§5 verdict decision table)

deny + enforced → `changed`, claimType `source-observed`; single-rule deny →
NO `verdictRuleIds` (nothing to apportion); mixed-severity deny with recorded
`blockingRuleIds` → `verdictRuleIds` = the blocking set; multi-rule deny with no
recorded set → `verdictRuleIds: []` (no rule credited) + reason appends "which
rules blocked is unavailable"; deny delivered-but-unenforced (`enforced:false`)
→ verdict ABSENT / claimType `unavailable` (a deny that never enforced is not
`changed` — the stage-lookup-advisory path); advisory fire → `unavailable`;
non-fire dispositions (silent / stage-hit-no-rules) ignored; multi-mouth
`parentId` chain folds to ONE verdict + `enforced` read across the whole chain;
retry detection: same act (`actionContext` || `actionContextSha256`) in a later
DIFFERENT chain → `retriedUnchanged:true`; `buildChainIds` multi-hop
(grandchild→root) so one evaluation is not a false retry; idempotence (prior
conformance line suppresses re-annotation) EXCEPT on retry-improvement and
scope-migration; `tallyByRule` full verdict vocabulary
(changed/conformed/breached/no-effect/vacuous) + per-rule scoping +
`awaitingJudgment`; `retirementCandidates` = fires>0 && changed+conformed==0 &&
awaitingJudgment==0 (no-effect counts as measured; all-awaiting and never-fired
excluded); `appendConformanceAnnotations` writes `phase:'conformance'` lines.

## test21 flakiness fix (unexpected FAIL → resolved)

The first full-suite run of this session hit an **unexpected FAIL in
test21_retire_restore** (arm D/E). Root cause: the **retire guard (Finding 21)**
refuses to retire a concept carrying an **undismissed `possible_duplicate_of`
pair flag** (the "erase rather than answer" guard). Within a test circle, the
auto pair-detector intermittently pairs structurally-similar / token-sharing
sentences (the reactor and harbor-tug templates) → retire refused → ARM D/E
failed. Verified flaky (full-suite + first standalone run failed; two
subsequent standalone runs passed). The recovery is the documented Finding-21
recipe: `memory_resolve{conceptAId, conceptBId}` →
`{action:'pair-flags-dismissed', rowsUpdated:2}` → retire proceeds.

Fix: added a `dismiss_dup_pairs()` helper to test21 that queries the
`memory_edge` table for undismissed `possible_duplicate_of` pairs on a concept
and dismisses them before each retire (ARM A/D), with a defensive retry arm for
ARM E/F. Re-ran 4× standalone (all pass) + a full-suite coverage run (green).
This is a test-robustness fix, not a product fix — the guard is correct product
behavior, the test had to handle it. Documented at
`contradiction-processing.md` §4a.

## Methodological insight (coverage-target selection)

`cov-map.cjs` counts **total source lines** (incl. comments) as the denominator,
so shim modules with heavy doc comments (db/index.ts 154→37 exec, project-dir.ts
19→4 exec, bootstrap.ts 85→34 exec) show misleadingly-low % — the metric
understates reality. When picking coverage targets, judge by **non-comment
executable-line density**, not the bare %. The next genuinely-actionable gaps
after this run are real-core modules: **core/retrieval.ts 52.5%** (202/385),
cli/cli.ts 49.6% (136/274), cli/materialize-cli.ts 68.9% (496/720).
