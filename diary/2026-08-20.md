# 2026-08-20 — Run 51 (E2E / coverage): core/conformance.ts pure-function driver (issue #18, DIRECTION #1)

## Priority taken

DIRECTION (supervisor run #8) priority #1 was `[E2E] core/conformance.ts line
coverage scenario` (monet-e2e#18): the largest non-deprecated core gap at 33.1%
(169/510). The prescribed route was a "`monet gate` evaluate path". Reading the
source first made clear that route does **not work**: `engine.runConformancePass`
— the sole caller of `computeConformance` — is **not wired to any command or
tool on either the shipped 1.6.3 binary or `main`** (verified: grep finds only
its definition in the source tree; the §5 "callable now, scheduled when the
consumer exists" comment confirms it). `monet gate` writes gate-journal
disposition lines but never runs the pass that consumes them.

So the conformance "cheap half" — the §4/§5 verdict decision table — is
reachable only as a pure function. This run covers it with a **direct driver**
bundled from core SOURCE (esbuild, alias `@conformance-src` →
packages/core/src/conformance.ts, no native deps), run under the same
coverage-attribution mechanism as the CLI/MCP suite.

## Conformance contract pinned (the §4/§5 verdict decision table)

deny + enforced → `changed`, claimType `source-observed`; single-rule deny →
NO `verdictRuleIds` (nothing to apportion); mixed-severity deny with recorded
`blockingRuleIds` → `verdictRuleIds` = the blocking set; multi-rule deny with no
recorded set → `verdictRuleIds: []` (no rule credited) + reason appends "which
rules blocked is unavailable"; deny delivered-but-unenforced (`enforced:false`)
→ verdict ABSENT / claimType `unavailable` (a deny that never enforced is not
`changed` — the stage-lookup-advisory path); advisory fire → `unavailable`;
non-fire dispositions (silent / stage-hit-no-rules) ignored; multi-mouth
`parentId` chain folds to ONE verdict + `enforced` read across the whole chain;
retry detection: same act (`actionContext` || `actionContextSha256`) in a later
DIFFERENT chain → `retriedUnchanged:true`; `buildChainIds` multi-hop
(grandchild→root) so one evaluation is not a false retry; idempotence (prior
conformance line suppresses re-annotation) EXCEPT on retry-improvement and
scope-migration; `tallyByRule` full verdict vocabulary
(changed/conformed/breached/no-effect/vacuous) + per-rule scoping +
`awaitingJudgment`; `retirementCandidates` = fires>0 && changed+conformed==0 &&
awaitingJudgment==0 (no-effect counts as measured; all-awaiting and never-fired
excluded); `appendConformanceAnnotations` writes `phase:'conformance'` lines.

## Notes / pitfalls

- os.homedir() on POSIX respects `$HOME` when set — my first journal-divergence
  assertion (expecting the journal to ignore a fake HOME) was WRONG; the correct
  contract is: journal follows `$HOME` via os.homedir() but STILL has no
  project-local `.monet` rung and no USERPROFILE fallback (the true divergence
  from getMonetDir). Fixed the driver to pin the accurate version.
- For a known host (claude-code), a lone-surrogate ANCHOR fails the per-host
  anchor validator BEFORE reaching the encoder (format throws the
  "anchor is not valid" message, not "not encodable"); to exercise encodeField's
  catch for the anchor you must use an UNKNOWN host (no validator). Session-id
  lone-surrogate hits encodeField directly on a known host.
- Across this run (test43+test44) two pure-module driver tests were authored; one
  (spans) advanced the coverage metric meaningfully, the other (db/index) proved
  the module was already line-maxed by the CLI bundle. Driver authorship is
  valuable as durable functional contract regression even when line coverage is
  unchanged.
