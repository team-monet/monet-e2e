# Coverage triage — upstream-test false-lead map

> RE run 58 (2026-08-21). The monet-e2e raw line-coverage metric has saturated
> (~84%). This doc maps every remaining sub-85% module to its *independent
> verification status* so a driver is never written just to lift a number that
> upstream unit tests already guarantee. Complementary to `coverage-gaps.md`
> (the raw per-module table, regenerated by `scripts/cov-map.cjs`).

## The lens

For each low-coverage module, ask the run-56 question first: *is the uncovered
logic already asserted by an upstream unit test in the public monet monorepo?*
If yes → the monet-e2e gap is a **coverage-metric false lead**: a driver re-drives
behavior upstream already proves, adding % but zero independent verification.
Only modules with **no** upstream test are genuine additive targets.

## Implication

Raw % is not a discriminating work queue anymore. Strategy should move to:
(a) report coverage only over the NOT-upstream-tested module set; and/or
(b) treat the behavioral XFAIL matrix (RE-issue verification) as the primary
    work source; and/or
(c) if one honest % lift is wanted, accept a `core/resolution.ts` driver.
